### 业务前提约束（硬性，开发必须遵守）
1. 后端接口、数据表、业务逻辑完全不动，只开发小程序端 wxml / wxss / js；全部数据请求沿用现有接口，**禁止新增后端接口、禁止修改表结构**。
2. 已上线财务风控逻辑完整保留：课程下单二选一弹窗、promoter分享身份拼团/砍价确认弹窗，**JS业务判断逻辑完全原样保留，仅美化UI样式；forgo_share_reward字段依旧由后端强制校验，前端参数不可信**。
3. 小程序前端增加【纯学习模式 / 分享推广模式】切换开关：**仅控制页面组件显隐，绝对不能调用接口修改后端 users.identity 数据库字段；用户真实业务权限仍然由后端返回 identity=promoter 控制**。
4. 资产严格隔离展示：
   - 「可提现分享奖励」：推广收益，可以提现；
   - 「抵现金余额」：学习任务产出，仅抵扣学费，**不可提现**；两个钱包分开展示，不能混淆。
5. 字体约束：正文全部使用系统无衬线字体；书法艺术字体**只允许用于大标题、canvas海报；禁止正文小字使用艺术字体，避免可读性差**。
6. 多处页面埋入合规提示文案，不允许删除；规则页面分「简易用户版 / 完整官方版」双Tab。
7. 页面所有倒计时、名额状态、补位次数、考核时间，**全部渲染后端接口返回数据，前端不写业务计算逻辑**。

## 需求原文
现象：课程列表页 `/courses` 课程卡片只展示名称、简介、价格、标签，没有【立即购买/我要买】【发起拼团】【发起砍价】操作按钮；课程详情页 `/course/:id` 页面底部/价格区域缺失【我要买】【发起拼团】【发起砍价】按钮组，用户无法完成购课，业务阻断。

修复要求：
① 课程列表页每张课程卡片底部增加操作按钮组：主按钮「立即报名（我要买）」；课程支持拼团/砍价时显示「发起拼团」「发起砍价」；角标【拼团】【可砍价】保留不变。
② 课程详情页价格模块下方/页面底部放置操作按钮组：主按钮「立即报名（我要买）」、次级按钮「发起拼团」「发起砍价」；不支持的类型直接隐藏按钮不置灰；点击立即报名弹出原有二选一下单弹窗（业务 JS、forgo_share_reward 逻辑不动）；点击发起拼团/砍价跳转对应页面。

约束：后端接口/业务逻辑/弹窗判断逻辑全部不动，只补前端 UI 按钮与跳转事件；主按钮用全局 CSS 变量 `--color-cinnabar` 朱砂红，次级按钮用次要样式；移动端按钮尺寸适配。

验收点：列表卡片可见下单按钮并正常跳转；详情页底部完整出现立即报名/发起拼团/发起砍价；点击立即报名正常唤起下单二选一弹窗；不支持拼团/砍价的课程对应按钮自动隐藏；promoter 身份进入拼团砍价依旧正常弹出身份确认弹窗。
